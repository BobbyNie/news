  5. Google 用 6/5 官方 recap 继续主推 Gemini 3.5 与 Managed Agents — 虽然底层能力首发在 5 月 I/O，但 6 月 5 日的官方回顾再次集中强调 Gemini 3.5、Gemini Omni、Managed Agents in the Gemini API 和 AI Studio，说明 Google 当前平台竞争重点已转向 agent runtime 与开发栈。平台竞争 Google · Managed Agents

分主题详情

产品主线：记忆正在从静态存档变成持续更新的上下文系统

  • Dreaming V3 是本窗口最强的用户侧产品更新。OpenAI 的重点不只是“记住更多”，而是让记忆会随着时间自动修正，减少过期和矛盾信息。OpenAI
  • 这会直接影响长期任务、持续协作和个性化体验，也会把“上下文 freshness”变成下一轮 AI 助手竞争点。
  • 配套的 ChatGPT release notes 也同步确认这是面向 Plus/Pro 美国用户的当日上线更新，并计划扩展至更多国家和免费层。ChatGPT release notes

开发者工具：安全能力正在并入主生成路径

  • OpenAI 在 API release notes 中把 moderation scores 直接并入 Responses API 和 Chat Completions API 的生成响应，意味着开发者不必再总是拆成“先生成、再单独审核”的两段式流程。OpenAI release notes
  • 这类更新的价值不在 headline，而在真实工程摩擦变小：日志、审计、告警和产品 UI 都更容易围绕单次响应统一落地。
  • Google 则从另一侧推进平台竞争：Managed Agents in the Gemini API 提供受管 Linux 沙箱、代码执行和持久环境，并允许用 AGENTS.md / SKILL.md 定义 agent。6 月 5 日的 recap 表明这条线仍在被持续强化。Google Managed Agents

治理与风险：大厂开始把 agentic workflows 当作能力边界处理

  • OpenAI 的 blueprint 继续推动“发布前评估 + 联邦协调机构 + 跨政府韧性计划”的路线，核心是先把最强模型纳入更制度化的前置评估，但不把部署决定完全交给政府。OpenAI blueprint
  • Microsoft 的 6 月 4 日文章更进一步，把风险拆成四层：通用模型、专用生物工具、实验室自动化和 agentic systems，并强调真正危险的是这些能力被工作流式拼接后形成的复合能力。Microsoft
  • 这说明“Agent 能做更多事”已经不只是效率叙事，也在变成安全评估和权限边界设计的中心问题。
